# 近期 Git / Paper Assistant / 协作需求整理

## 已确认的目标

同一个论文项目、同一个 Git 仓库，可以有多个分支工作区。用户独立选择分支；同分支工作区内继续实时协作，不同分支工作区隔离，通过显式合并交换修改。分支工作区不是用户另建的论文项目。Clone 则明确创建一个独立的新论文项目。

## 已实现并部署到 r49 的功能

- Repositories、Changes、Graph 三个区域与分级菜单；项目名称/图标、Publish Branch、原生 Git 操作、错误和恢复界面。
- Graph 详情再次点击收起、侧栏尺寸调整、离开 Git 菜单关闭主 Graph、统一图标与排版。
- 日期 DD-MM-YYYY HH:mm:ss；Description 左对齐，Date/Author/Commit 标题和数据居中；Author 超长省略且悬停显示完整姓名。
- Read Only、Ask for approval、Approve for me、Full Access 四个权限选项。Full Access 的容器根文件系统可写，但仅挂载当前项目所需卷路径；无宿主目录、Docker socket、Shell 网络，Git 元数据及应用凭据保持保护。
- Approve for me 采用保守的只读命令白名单；其他 Shell 命令需要绑定用户、会话和完整命令的一次性审批；原始输入不能绕过审查。
- Paper Assistant `/git <操作> [参数]`，48 种操作形式，`/git help` 和单项帮助；复用原生 API、当前编辑器保存等待、权限和预览确认。
- 原生 Git 导入包含项目写锁、文件版本/身份检查、操作前快照和未完成传输恢复。

已实现不等于多人分支协作已经安全：当前 r49 仍是一项目一份编辑绑定和共享 index；任一用户 checkout 会切换共享项目。Shell 磁盘写入还不是协同文档事务，可能在文档向磁盘导出时被覆盖。

## 待实现的核心行为

1. 项目共享、分支工作区隔离；A 切换分支不能替换 B 正在编辑的内容。
2. 同分支用户共享实时协同文档；跨分支使用不同文档身份、消息房间、保存/历史/编译命名空间。
3. 浏览器会话绑定 workspaceId 和 epoch，防止离线旧编辑写入切换后的分支。
4. Git Graph 实时标记用户/会话所在分支、基准提交、未提交状态；“查看历史”与“实际编辑”必须区分。
5. 用户头像定位只能移动 Graph 视图，不自动改变观察者分支。支持多人同位置、多标签页、断线超时以及被过滤节点的定位。
6. 同一文件、不同文件、重命名/删除、暂存竞争、合并和 Shell/AI 回写都不得静默丢失修改。
7. 跨分支合并先在隔离工作区准备，应用前校验目标工作区最新版本；保留双方内容和可恢复记录。
8. 后台自动任务按项目/分支管理，一个任务不因用户或标签页增加而重复运行；不用要求每人分别开启 Git 同步。
9. 自动检查点、commit、fetch、pull、push 分开配置；默认禁止自动强推、硬重置、丢弃或代替用户选择冲突一方。
10. 协作操作权限、任务归属/凭据、共享冲突处理、持久审计与恢复、论文元数据和编译规则需要纳入设计。

## 不可省略的验收条件

- 不承诺网络零延迟；必须显示保存/离线/同步中/冲突/恢复状态，并验证重连后的收敛。
- 服务器无法假定已获得失联浏览器的缓冲内容；不得把失联用户算作保存成功。
- Full Access 不等于可以绕过协作文档版本检查。
- Git index/tree/HEAD 与 Overleaf 文档、浏览器缓冲、远程 ref 都要校验；HTTP200和单用户测试不够。
- 现有项目平滑保留；迁移前可恢复、失败可回退，不复制或公开用户凭据。
- 测试使用独立合成项目与远程仓库，避免修改用户论文和真实远程。

详细的14项候选能力和10个防覆盖场景见 ../git-native-plugin/collaboration-review-r49.md。本文件确认目标，不声称这些协作行为已实现。

## 当前实施与新增讨论

基线提交和初版方案已完成并推送。用户随后授权六阶段实施和多用户完整性测试；当前仅部分基础源码和隔离测试完成，不能将整个协作方案标为完成。

新增讨论已统一整理为 [实现要点 W01–W38](implementation-points.md)：未推送分支可见性、用户实际位置、外部 push 的发现与安全应用、项目级冲突通知、多人消解协调、重连恢复、远端强推/删除、重复任务、未知推送结果、权限撤销与论文资源完整性。

统一约定：网页协作以 Overleaf 服务端为中心；远端是独立的交换/发布端。fetch 更新 Git 对象和远端跟踪状态，正文应用另走防覆盖事务。确认冲突后通知授权写作者，草稿隔离消解，不能直接覆盖共享论文。

实施顺序与完整测试矩阵见 [实现方案](implementation-plan.md) 第 10、12–15 节。当前通过和失败证据见 [notes.md](notes.md)，而不是从需求描述推断实现状态。
