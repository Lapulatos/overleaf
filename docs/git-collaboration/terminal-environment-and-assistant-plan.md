## 1. 要实现的使用体验

在 Overleaf 设置左侧新增独立项 **「运行环境与终端」**。管理员定义可用环境及资源上限，用户在允许范围内选择；Paper Assistant 与手动 Terminal 使用同一个指定环境。

用户应能完成以下流程：

1. 在设置里选择可联网的开发环境，配置 CPU、内存、可用 GPU，允许安装系统软件。
2. 在当前分支/提交位置新建 Terminal，得到该位置文件构成的独立执行环境。
3. 直接运行 `apt`、`pip`、`npm` 等命令，安装允许的工具；关闭面板或切换网页分支不会改变这个环境。
4. 指定一个 Terminal，让 Paper Assistant 读取输出、输入命令、响应交互，并随时取回控制权。
5. 在 SSH 主机列表选择远程主机，通过 Terminal 登录、执行命令、安装工具和传输文件。
6. 停止后按策略保留软件和文件，下次进入继续使用；界面明确区分环境保留、shell 已退出、任务仍运行。

**网络应是明确、可管理的能力，不应继续硬编码为一律关闭。** 按本次需求，推荐新建「开发环境」模板默认允许公网访问；是否允许内网远程主机、哪些端口、代理和额度由管理员配置。离线模式保留为可选项。旧 Session 不因模板变化而偷偷获得新权限。

## 3. 设置页面如何组织

只增加一个一级入口，不把大量设置塞进 Paper Assistant 权限弹窗。页面顶部展示：

> 当前环境：开发环境 · 联网 · 可安装工具 · 2 CPU / 2 GiB · GPU 无
>
> 生效范围：新建环境　　[保存设置]

以上数值是建议初始模板示例，须受 runner 实际容量与管理员总额度约束，不能承诺所有设备都支持。

页面采用与现有设置一致的字号、图标和控件。每组只保留简短介绍、当前状态及具体操作；高级字段默认收起，不再添加大段 “How it works”。

| 分组 | 默认显示 | 高级选项 |
| --- | --- | --- |
| 运行环境 | 模板、镜像、执行位置、本地/远程 runner | 镜像摘要、架构、PID、临时空间、环境变量引用 |
| 计算资源 | CPU、内存、GPU、存储用量/额度 | Swap、设备 ID、项目并发环境数 |
| 网络与软件 | 联网开关、系统软件安装、连接测试 | 允许的目标、端口、代理、DNS、软件源 |
| SSH 主机 | 主机卡片：名称、连接状态、连接/编辑/删除 | 地址、端口、账号、指纹、凭据引用；后续支持跳板机 |
| Agent 控制 | 默认审批模式、允许接管、当前控制者 | 可接管环境、授权时长、远程目标范围 |
| 保留与清理 | 保留已安装软件和文件、到期时间、用量 | 空闲停止、日志期限、配额告警、清理预览 |

MCP 为左侧工具栏 Plugin 下方的独立入口，服务卡片支持搜索、连接、工具授权及 README 阅读；不放在此设置分组内。

**管理员与普通用户看到同一个结构，权限不同：** 管理员编辑允许的镜像、网络、资源上限和保留策略；项目管理员选择项目默认模板；成员只能在授权范围内选择自己的环境与私有 SSH 凭据。不能把项目所有者直接等同于整个平台管理员。

被策略禁止的选项显示锁定状态和一行原因；不允许界面显示开启、后端仍偷偷关闭。顶部区分「已保存模板」和「当前 Session 实际配置」，二者不同则显示“当前会话使用旧配置”。

Paper Assistant 的权限弹窗保持四个短选项，底部只显示实际状态，例如：

> 🌐 联网　📦 可安装工具　[运行环境设置]

## 4. 权限、网络、安装能力的关系

### 4.1 四模式只表达 Agent 如何行动

| 模式 | Agent 行为 | 手动 Terminal |
| --- | --- | --- |
| Read Only | 只能读取，不修改项目或安装软件 | 进入只读环境 |
| Ask for approval | 命令执行前请求批准 | 正常交互，受环境权限约束 |
| Approve for me | 自动审查命令，无法确认时询问用户 | 正常交互，不出现额外 Command 表单 |
| Full Access | 在已授权环境内直接执行 | 使用同一环境能力，不自动获得宿主机权限 |

联网、系统软件安装、CPU、内存、GPU 来自环境配置。Full Access 不再被误解为“网络、GPU、所有系统能力自动全部打开”；选择开发环境并启用相关能力后，Full Access 才能直接利用它们。

Ask for approval 与 Approve for me 之间切换不终止 shell。Read Only 与可写环境之间的改变需要新环境或显式迁移；不得静默结束旧 Session。撤销 Agent 授权立即终止控制租约；管理员紧急网络撤销可立即执行，并显示原因。这与普通模板更新只影响新环境是两种操作。

### 4.2 网络配置必须真正执行

提供三种策略：离线、允许公网、指定目标。默认开发模板允许公网 HTTP/HTTPS 和必要 DNS；管理员可增加其他出站端口。SSH 主机授权另含目标地址与端口，可覆盖经批准的内网主机，不等于开放全部内网。

执行要求：

- 所有容器出站经过 runner 管理的出口规则；IPv4/IPv6、DNS、代理、重定向后目标都要一致处理。
- 单纯从 `none` 改成 bridge 不等于完成网络隔离。必须阻止未授权访问宿主控制面、其他项目、平台内部服务及元数据地址；批准的远程主机作为明确例外。
- 软件源/HTTPS 代理可以简化包下载，但不能假定任意命令都会遵守代理环境变量。直接 socket 出站同样受规则限制。
- UI 的测试分别报告 DNS、HTTPS、软件源、SSH 目标连通性。失败分清策略阻止、解析失败、目标不可达和认证失败，不能统一报“服务连接中断”。
- Paper Assistant 的公共资料获取、Terminal 出站、SSH 目标授权是三条不同通道，在设置中标清作用范围，不能复用一个开关假装全部生效。

### 4.3 软件安装

提供「仅项目依赖」和「允许系统软件安装」两种环境能力。前者使用项目内 venv、用户包目录等；后者允许指定容器内的包管理操作。

安装环境采用可写容器层，按包管理器测试确定必要 capabilities（重点验证 CHOWN、SETUID、SETGID、FOWNER 等，而非直接宣称加某一项即可）。保留基本隔离，不用 privileged、宿主网络或挂载 Docker socket 解决安装失败。

安装模板同时配置可写 HOME、包缓存和足够的临时空间；Git 元数据继续只读保护，不能靠放开 `.git` 写入获得安装能力。

容器内 root 可直接使用 apt；非 root 环境需要明确的受控安装操作或预装镜像，不能依赖不存在的 sudo。包脚本需要 systemd、内核模块等能力时，报告不支持并引导选择合适的远程运行环境。安装终端工具不会自动改变 Overleaf 的 LaTeX 编译镜像；编译维护入口保持独立。

## 5. 配置模型与服务端接口

配置覆盖顺序：**平台允许范围 → 项目默认模板 → 用户可选项 → Session 不可变配置快照**。服务端校验权限、容量和配额后计算 effectiveConfig；超限应明确拒绝，不能静默降配后显示申请值。

建议新增以下数据对象，名称为拟议设计：

| 对象 | 关键内容 |
| --- | --- |
| EnvironmentProfile | 版本、镜像摘要、runner 类别、资源、网络策略引用、安装能力、保留策略 |
| Environment | 所有者、逻辑项目、容器/runner 身份、来源 workspace/分支/commit、已保存修改快照摘要、effectiveConfig、状态 |
| TerminalSession | environmentId、shell/PTY 身份、所有者、名称、状态、输出游标、创建/停止时间 |
| SSHHost | 名称、地址/端口/账号、信任指纹、凭据引用、授权成员、允许目标规则 |
| McpServerRegistration | 用户/项目范围、transport、endpoint 或服务模板、版本、凭据引用、允许工具、连接状态 |
| AgentControlLease | taskId、sessionId、用户、目标环境/主机、权限版本、到期时间、撤销状态 |

拟议 API：读取能力与有效配置、管理 Profile、创建/停止/重开/删除 Environment、列出/连接 Session、增量读取日志、管理 SSH 主机和连接测试、获取/释放控制租约。每个接口校验用户与项目归属；写操作校验 CSRF，启动请求带幂等键，错误不返回宿主路径或秘密。

资源参数映射由后端生成，不向前端提供任意 Docker 参数文本框。CPU/内存/PID 映射到对应限制；GPU 仅在 runner 检测支持时暴露。磁盘额度只有在存储驱动或配额后端能实际强制执行时才显示“硬限制”，否则显示实际能力与告警，不伪造保证。Docker 的 CPU、内存与 GPU 约束需结合宿主支持配置。[Docker 资源约束](https://docs.docker.com/engine/containers/resource_constraints/)

环境启动采用：校验 → 预留额度 → 创建出口规则/存储 → 记录启动尝试 → 创建容器 → 核验实际参数 → 标记可用。失败释放已确认未使用的额度；Docker 超时属于结果未知，先核验身份，不能重复创建。复用现有生命周期日志并扩展，不能丢弃它。

## 6. 环境保留与 Session 管理

先分清三个对象：**环境是软件和文件，Session 是 shell，任务是正在执行的工作。** 同一环境可以有多个 Session；每个列表项仍显示所属用户头像、分支、commit、环境和当前目标。

| 用户操作 | 应有结果 |
| --- | --- |
| 关闭面板、切换 Paper Assistant/Terminal tab | 只改变界面，不结束进程 |
| 断开浏览器 | Session 按保留策略运行；重连同一个 PTY |
| 退出 shell | Session 结束，可查看完整历史；环境仍保留 |
| 在保留环境中打开新终端 | 创建新 shell，保留安装的软件和文件；不伪称恢复旧进程 |
| 停止环境 | 明确提示影响的 Session/进程；保存可持久数据 |
| 删除 Session 记录 | 删除/隐藏该会话历史记录，不连带删除仍被引用的环境 |
| 删除环境 | 列出所有关联 Session、文件及未回源变更；确认后才释放资源 |

优先使用容器内 tmux 保留 shell，并由独立会话服务适配其控制接口；容器主进程改为受控环境 supervisor，不能继续把环境寿命直接绑定到某一次交互桥接进程。Web 重启不影响 PTY；runner 重启后核验容器、PTY 与日志状态。重开环境是新一次生命周期尝试，记录与旧尝试的关系，不强行复用已停止 attemptId。

已安装系统软件保存在保留容器层；项目与用户文件使用独立受控存储。删除容器或换镜像不会神奇保留 apt 安装结果：迁移使用安装清单、锁文件、Dockerfile 或明确的镜像构建产物，先预览影响。机器故障后的恢复能力须通过备份/重建验证，不能把“保留同一容器”说成完整灾备。

日志按字节游标持久化，保留 ANSI 与尺寸事件供只读终端回放；设置容量、截断提示及保留期。密码输入阶段不录入输入、不交给模型；普通输出也可能包含秘密，需要屏蔽/脱敏和明确日志范围，不能保证任意命令输出都可自动识别为安全。

## 7. SSH 远程连接

### 7.1 本期 SSH 能力

基础环境提供 OpenSSH 客户端。受管连接优先评估独立 broker 内的 ssh2，与手动 OpenSSH 共用 Session 状态接口；长期私钥不进入拥有 root 的工作容器。设置里新建主机卡片，填写名称、地址、端口、账号、认证方式，测试连接后可从 Terminal Session 管理进入。

推荐「受管 SSH Session」作为 Agent 操作远端的入口。系统绑定目标主机身份并显示 `远端 · 主机名 · 用户 · 工作目录`，同时保留本地环境的分支/commit 来源。**远端目录不天然等于当前分支快照**；上传代码需显式选择目标目录、生成输入清单和版本摘要，已有目录先比对，不直接覆盖。

用户仍可手动输入 `ssh`，但不能仅凭 shell 提示符推断实际远端身份。手动嵌套连接标记“目标未由平台验证”；Agent 自动操作远端前应切换到受管连接或重新确认目标。

认证与信任：

- 私钥加密保存于服务端凭据系统；UI 和模型只拿引用。优先使用短期证书或仅对当前授权目标可用的签名代理。
- 不把长期私钥写入 Agent 可读、且可能有 root 的工作容器。只读挂载也不能防止该容器读取密钥。签名代理同样是可用权限，必须限目标、限时、可撤销，禁止默认转发到远端。
- 首次连接需用户通过可信来源核对主机指纹；指纹变化阻止自动重连。禁止默认关闭 StrictHostKeyChecking。
- 密码/MFA 由独立敏感输入通道交给用户；期间暂停 Agent 控制与相应日志采集，不把密码输入放入对话。
- 默认不开启端口转发、任意 ProxyCommand 或 agent forwarding；需要时作为单独管理员授权能力。主机校验与转发选项以 OpenSSH 语义为准。[OpenSSH 配置手册](https://man.openbsd.org/ssh_config)

### 7.2 连接与权限边界

明确区分连接中、已连接、已断开和认证失败。断开 SSH 只表示连接结束，不能据此宣称远端命令已停止或仍在运行；界面如实显示未知状态，不自动重放可能已经执行的命令。

远端账号权限决定实际操作范围，本地 Full Access 不提升远端权限。本地容器的 CPU、内存、GPU 配置不控制远端主机；SSH 页面应明确标注这一点。支持基本文件上传下载、目标目录确认、覆盖提示及失败重试，不在本期增加远程作业管理。

## 8. Paper Assistant 如何接管 Terminal

接管入口放在 Terminal 工具栏：用户选择 Session 后点击「交给 Assistant」；状态显示用户头像/Agent 工作状态，提供「收回控制」和「中断命令」。全局设置只决定默认策略，不代表 Agent 自动取得所有终端。

拟议工具：`list_terminal_sessions`、`acquire_terminal_control`、`read_terminal_output(cursor)`、`write_terminal_input`、`run_terminal_command`、`interrupt_terminal_command`、`release_terminal_control`。请求和返回均携带 Session、环境、远端目标（如有）及权限版本。

执行规则：

1. 任务绑定用户明确选择的 Session；网页切换分支不能切换 Agent 目标。
2. 控制租约保证同一时间只有一个写入方，用户可随时取回；断线、超时、任务结束或权限撤销时回收租约。
3. Agent 通过同一 PTY 输入和增量读取输出，保留 shell 的 cwd、环境变量、虚拟环境及交互程序状态。
4. 若另开 exec，必须标为“独立命令”，不声称继承当前交互 shell 的状态。
5. 每次执行重新校验租约、审批模式、目标与网络策略；不能只在任务开始时检查一次。
6. 普通交互输入不能可靠推断“命令完成”；结构化命令采用 shell integration/退出码边界，未支持的交互程序返回“等待输入/仍运行/状态未知”，不伪报成功。
7. 工具中断只终止当前命令或发送中断，不销毁整个环境；有输出背压、大小限制和超时。
8. 修改 harness 的硬编码禁网说明，改为传入已核验能力；没有绑定会话时不能把模型内部 shell 当成用户正在看的 Terminal。

### 8.1 MCP 外部工具接入

在左侧工具栏 Plugin 下方增加独立 MCP 入口，一服务一卡片，支持服务/工具模糊搜索、简短描述、连接测试、启停、凭据与工具级授权；工具清单折叠显示。Skill 指令和 MCP 工具保持各自含义，不批量生成无必要的新命令。

复用官方 TypeScript SDK 接入受管 stdio 和远程 Streamable HTTP，由服务端 McpBroker 将允许的 tools 转为现有 harness 的动态工具。stdio 在受控容器运行；HTTP 使用每用户认证与出口策略。不得一键解除现有 MCP 禁用保护并继承全部宿主配置。

保留当前未授权服务默认禁用的测试，新增授权服务连接、调用、撤销、超时与跨用户隔离测试。MCP 自报只读标注不能代替系统权限判断。工具列表变化需重核授权；凭据不进模型；写调用超时不自动重放。MCP 网络策略独立显示，但不能绕过被禁止的目标。

Terminal 的内部 MCP server 可复用同一 Session Service，但不默认公开到外部；本期必须完成的是外部 MCP 客户端接入。SDK 版本和协议兼容需锁定后验证，详细参考与版本差异见组件选型文档。

## 9. Terminal 修改与 Git 如何衔接

环境创建时固定文件快照及来源：逻辑项目、workspace、分支、commit、未提交但已保存编辑的摘要。切换到其他分支后，已创建环境不变。

Git Changes 增加环境来源选择，自动检测该环境文件变化。用户在现有差异视图查看，不在 Terminal 堆叠空洞的 Review/Apply 按钮。环境修改回源时校验创建基线、当前分支头和协作编辑版本；目标分支与网页当前分支不同要写明，不能写错分支。发生分歧走三方合并；远端文件先下载到受控暂存区，再决定是否纳入项目或 Git。

## 10. 实现步骤与完成标准

顺序是依赖关系，不是时间承诺。每步通过再扩展，不能仅凭设置页能保存就宣布能力已完成。

| 步骤 | 实现内容与主要位置 | 验收条件 |
| --- | --- | --- |
| P0-1 配置与能力模型 | 新增 Profile/Environment schema、管理员 API、runner capability probe；连接 AccessPolicy 与实际配置 | 超额/越权请求被拒绝；旧 Session 保留原快照；不支持 GPU 明确禁用 |
| P0-2 可联网、可安装环境 | 改 TerminalContainer 与 shell-docker-adapter 参数生成；出口策略、包管理权限、软件源诊断 | 隔离容器真实 DNS/HTTPS、apt update + 安装一个测试包、venv pip 与 npm 安装成功；离线和未授权目标确实被拒绝 |
| P0-3 独立设置页面 | 注册「运行环境与终端」；资源、网络、安装能力、实际状态；四模式仅保留短选项 | 管理员/成员权限正确；刷新后设置保留；失败不显示已启用；对现有会话说明生效范围 |
| P0-4 环境和 Session 分离 | supervisor/PTY 服务、持久日志、重新连接、重开环境与配额清理 | 关面板不退出；Web 重启可重连；退出 shell 后文件/软件仍在；恢复失败不显示 Running |
| P1-5 受管 SSH | 主机卡片、凭据代理、指纹、连接测试、远端标识、上传暂存 | 在受控 SSH 主机真实连接/执行/上传下载；错指纹被拒绝；凭据不进入模型/日志；网络拒绝有具体原因 |
| P1-6 Agent 接管 | harness 工具桥接、租约、审批、同 PTY 输入输出、用户收回、远端授权 | Agent 看到用户执行的输出，继承 cwd/变量；可中断；跨用户拒绝；SSH 目标不漂移；敏感输入暂停接管 |
| P1-7 Git 与环境变更 | 环境变化检测、来源差异、基线校验与回源合并 | 从 A 创建环境后切到 B，命令仍修改 A 的快照；回源不覆盖并发编辑；传入文件来源可追踪 |
| P1-8 MCP 接入 | 官方 SDK、McpBroker、设置卡片、tools 动态适配、凭据/网络/审批统一校验 | stdio 与 HTTP 均能连接与调用；OAuth/撤销实测；未知结果不重复写；未授权宿主配置仍禁用 |

P0 的完成含义是“设置里选择联网安装环境，真实能用、能保留”；P1 的 SSH、Agent 接管、MCP 接入和 Git 文件衔接同样属于本期基础设施，必须全部完成并验收，不能作为可选尾项。

首轮验收用专用测试项目、容器和受控 SSH 主机，不修改用户论文或借用生产会话。保留失败记录与实际生效参数（脱敏）。GPU 只有在真实兼容设备运行成功才标记通过；本机不具备条件时列为待验证，不用模拟测试替代。

## 11. 发布、迁移与回退

先完成隔离验收，再部署 18081，验证后部署同一版本到 18082。前端、Web、runner、Profile 版本分别记录，不能只更新 UI。

旧 Session 和旧 runner 排空迁移：仍运行的会话继续使用原版本，新环境走新 runner。不得为部署强行重启承载用户会话的 runner。旧数据没有环境字段时标记“旧版会话”，保留历史；不伪造可恢复容器。

发布失败时禁用新环境创建或回退新会话路由，保留已创建环境与输出，不做全量删除。迁移、清理和重建必须列出影响的具体环境及关联会话。敏感权限撤销按独立即时流程处理，不受排空策略拖延。

## 12. 建议采用的初始方案

先提供一个管理员可编辑的「开发环境」：公网联网、允许安装工具、建议 2 CPU / 2 GiB（以容量审批为准）、GPU 默认不申请、停止后保留环境，建议闲置保留 7 天并提前通知清理。用户可选择离线或只读环境；管理员可收紧默认值。

首期不提供任意 Docker 参数编辑器，不承诺内核模块/systemd 等完整虚拟机能力，不默认开放端口转发。本期完成“联网装工具 → 保留环境 → SSH → Agent 同会话操作 → 文件变更回源”的完整流程。

启动参数与隔离机制应由后端生成；Docker 容器可独立设置用户、资源与 capabilities，但不能把容器内 root 等同于不受限宿主访问。[Docker 运行参数](https://docs.docker.com/engine/containers/run/)

逐项页面实现与人工验收顺序（含 README 渲染）见 [实施清单](../terminal-environment-design/staged-implementation.md)。用户确认当前功能后才进入下一项。
