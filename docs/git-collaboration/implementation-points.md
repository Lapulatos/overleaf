# Overleaf 分支协作：实现要点与风险清单

更新：2026-11-11。本文汇总近期讨论，并补充需要验证的并发和恢复场景。**需求确定、推荐策略、源码完成、测试通过、部署完成是不同状态。** 具体实施顺序见 [实现方案](implementation-plan.md)，当前证据见 [执行记录](notes.md)。

## 1. 讨论已经明确的行为

1. 用户只看到一个论文项目；一个项目共享一个服务端 Git 仓库。
2. 每个分支有独立协作工作区。同分支实时协作，跨分支显式合并。个人切换分支不能改变其他人的编辑内容。
3. 浏览器会话与工作区绑定。同一用户的不同标签页可以在不同分支；不能只按 userId 保存位置。
4. Git Graph 同时表达服务端提交图、远端跟踪状态和协作者位置，但三者不能混为一谈。
5. 在 Overleaf 创建的分支和提交，即使尚未 push，也应对有权限的项目成员可见。网页之间通过 Overleaf 服务端同步，不经由 GitHub 转发。
6. 网页未提交修改不是 Git 提交节点，应显示对应工作区的未提交状态。查看历史提交不等于进入该提交编辑。
7. 外部用户可以直接向远端 push。Overleaf 必须发现远端变化、获取提交、通知网页，再决定如何安全应用正文。
8. fetch 与更新协作文档分离；发现远端更新不能直接覆盖网页修改。
9. 确认冲突后通知项目写作者，提供共享的处理状态；离线用户重连也必须获知未解决事项。
10. 冲突先在隔离草稿中解决，不能把冲突标记直接塞进正在共同编辑的论文。
11. 自动任务按项目/分支管理，不由每个用户或标签页分别启动。自动拉取应用与 AI 回写必须通过防覆盖验收后开放。
12. Shell 的 Full Access 仅限独立容器；不能访问 macOS 宿主目录、Docker socket，不能绕过协作文档事务。
13. Git 面板和 Paper Assistant `/git` 共用权限、预览、任务与错误处理。Clone 创建独立论文项目，不是内部工作区。
14. 必须以多个独立账号、浏览器会话和外部 Git 客户端进行验收，不能仅凭单用户测试或 HTTP 200 宣称完整支持。

### 1.1 早期界面和操作要求也属于验收范围

以下整理自本次对话，不以历史“已实现”描述替代逐按钮验证。已有功能记录见 [requirements.md](requirements.md)。

| 范围 | 用户要求 | 验收要求 |
|---|---|---|
| Terminal | 紧凑布局；输入到达底部时最新命令/光标可见 | 连续输出、窗口缩放、输入换行后不遮挡提示符；用户上滚查看历史时不强行拉回，重新输入可回到底部 |
| 权限 | 删除 Approved directories；支持四种权限模式；Full Access 仅容器内 | 容器边界和审批由后端执行；禁用项不能仅改成可点击而缺少实际能力 |
| Repositories | 真实论文项目名称、仓库图标、Publish Branch、More Actions | 长名称可辨识；发布按钮与上游状态一致；发布失败不能显示成功 |
| 两处 More Actions | Repository 与 Changes 使用分级菜单，复用共同操作 | Commit、Changes、Pull/Push、Branch、Remote、Stash、Tags 等动作逐一验证；Repository 的 Worktrees 与 Changes 的 View & Sort 分别保留适用语义 |
| 三个折叠区 | Repositories、Changes、Graph 标题空白区也可展开/折叠 | 点击动作按钮不触发折叠；键盘可操作；Graph 列表正常滚动，不只显示一条 |
| Git Graph | 离开 Source Control 自动关闭主图；工具栏单色图标，图标题可保留彩色标识 | 图标形状一致；Description 左对齐，Date/Author/Commit 标题和数据居中；Author 省略并悬停显示全名 |
| 日期 | DD-MM-YYYY HH:mm:ss，24 小时制 | 同一表格使用一致时区并可知其时区；固定格式，不混用本地化月/日顺序 |
| Paper Assistant | `/git <操作> [参数]` 和参数帮助，覆盖大部分基本 Git 操作 | 与按钮共用服务、权限、预览和错误语义；缺参数给用法，不猜测危险参数 |
| Clone | 输入远端 URL 后创建新的独立论文项目 | 有真实导入结果、权限、根文档和失败恢复；不把 Clone 当作现有项目的内部工作区 |
| 完整性 | 所有菜单、按钮和命令不能空实现 | 建立动作清单：入口→后端→实际效果→权限→错误恢复→测试证据；只打开子菜单不算功能完成 |

### 1.2 普通 Git 与 Overleaf 特有功能的边界

| 类别 | 例子 | 为什么需要单独实现 |
|---|---|---|
| Git 原生能力 | commit、branch、merge、fetch、push、stash、tag、worktree | Git 提供仓库操作；产品仍需接入参数、凭据、权限与错误处理 |
| Git 操作的协作适配 | checkout、pull、merge、reset、stash apply | Git 不知道浏览器缓冲、OT 队列或 docId，不能直接用磁盘替换代表协作完成 |
| Overleaf 特有能力 | 分支文档空间、实时用户位置、共同冲突处理、项目级自动任务 | 一个分支可能被多人同时编辑，需要会话、文档与任务的一致状态 |
| 论文特有能力 | 主文档、评论、历史、编译、二进制附件、Clone 成项目 | Git 文件树不包含全部项目元数据，文件合并成功不代表论文项目可用 |

## 2. 数据以哪里为准

| 数据 | 权威来源 | 网页显示规则 |
|---|---|---|
| 已被服务端接受的协作编辑 | 当前分支的协作文档与版本 | 同分支实时传播；明确保存、离线、待上传状态 |
| 浏览器尚未上传的编辑 | 该浏览器的本地缓冲/恢复草稿 | 服务器不得宣称已保存或将失联会话视为确认保存 |
| 服务端分支、HEAD、index | 项目共享的服务端 Git 仓库及分支工作区 | 未 push 也可见；不能把别的分支的脏内容带入当前分支 |
| GitHub 等远端当前 refs | 远端仓库 | 本地只能显示最后一次成功查询的结果和时间 |
| `origin/main` 等跟踪分支 | 最近成功 fetch 的服务端快照 | 可能落后于远端；不能标成绝对实时 |
| 在线用户所在分支 | 服务端验证的会话/工作区身份 | 与最后 push 的位置无关；断线显示最后在线时间 |
| 用户查看的提交 | 会话的查看意图，服务端校验可访问性 | 单独标“查看历史”，不修改编辑位置 |
| 外部提交作者 | Git 提交元数据 | 不能据此推断在线状态，不能仅凭同名/邮箱绑定真人账号 |

远端可以作为团队正式发布的参考基准，**不能因此隐去服务端尚未推送的工作或伪造用户停留位置**。外部客户端尚未上传的分支和本地修改不在 Overleaf 可观测范围内。

## 3. 问题、解决规则与验收点

下表的处理规则是实现依据，不表示已经实现。推荐的默认配置仍需在验收后固化。

| 编号 | 情况 / 风险 | 处理规则 | 最低验收 |
|---|---|---|---|
| W01 | A 切分支覆盖 B 页面 | 每分支独立文档身份、房间、文件树、历史和编译命名空间；只切换 A 的会话 | A/B 同文件编辑；A 切分支后 B 内容和 docId 不变 |
| W02 | B 创建未推送分支，A 看到旧位置 | 服务端共享 refs；事件通知重新取图；presence 独立于 push | 不配置远端也能看到新分支和 B 的真实编辑位置 |
| W03 | 同账号多标签页互相替换位置 | 以 sessionId 标记每个会话，编辑与历史查看分开 | 同账号两标签页处于不同分支，关闭一个不删除另一个 |
| W04 | 网络延迟、断线、漏事件 | 心跳、最后在线时间、过期状态；重连获取完整快照，再收增量 | 丢包、乱序、断线后不永久显示假在线/旧图 |
| W05 | 外部 push，网页不知情 | 项目级 Webhook/周期检查触发 fetch；所有授权网页刷新远端跟踪状态 | 外部客户端 push 后网页显示 incoming，正文尚未改变 |
| W06 | fetch 被误认为正文同步完成 | 区分已获取、待应用、冲突、已应用、待推送等状态 | 图已更新而编辑内容未应用时，界面明确说明 |
| W07 | 远端新提交遇到网页脏内容 | 保留脏内容；创建传入更新预览；禁止自动 stash/reset/discard | 同文件/不同文件均不丢字节；不冒充已合并 |
| W08 | 服务端和远端都有新提交 | 比较共同祖先并准备隔离合并；非冲突变化也需版本检查 | 分叉可解释，解决结果为正常新提交，不强推 |
| W09 | 已确认冲突只被某一用户知晓 | 持久冲突任务；受影响分支醒目提示，全项目授权写作者获得摘要 | 两分支多用户、重连用户均看到一致任务状态 |
| W10 | 两人同时消解冲突 | 处理租约与递增 fencing token；版本化保存草稿；旧处理者不得最终应用 | 租约转交、过期、迟到提交不会覆盖新解决结果 |
| W11 | 消解期间正文或远端继续变化 | 捕获 base/local/remote/版本向量；应用前重新验证，失配则重新预览 | 更新远端或正文后旧解决稿被拒绝，但草稿仍保留 |
| W12 | 远端强推、删除或改名分支 | 检测非快进/消失；保留服务端工作区、恢复引用和未提交内容；人工决定 | 不自动硬重置或删除仍有成员/草稿的工作区 |
| W13 | 自动任务重复、重启、超时 | 持久 operationId、单一执行租约、续租、fencing、退避、结果对账 | 重复投递不重复提交；超时后不盲目再次 push |
| W14 | push 成功但响应丢失 | 标记结果未知；查询远端是否包含本次提交，再决定完成/重试 | 模拟断响应，图和任务最终收敛且无重复提交 |
| W15 | 多人同时暂存/提交 | 分支共享 index；操作绑定 HEAD/index 内容指纹；提交前刷新预览 | A 预览后 B 更改暂存区，A 不会提交未审阅内容 |
| W16 | Shell/AI 写入与页面竞争 | 隔离草稿、基线清单、工作区/epoch/版本校验、统一事务回写 | status 刷新不抹掉 Shell 草稿；AI 旧结果不能写进新分支 |
| W17 | 离线旧操作重新上传 | 绑定原 workspace/epoch/docId；失配保存恢复草稿并提示比较 | 离线期间批量替换/重命名后，旧操作不会直接覆盖 |
| W18 | 同名文件重建、编辑后撤销 | 校验 docId 与单调版本，不能只比较路径和字节 | ABA、删后重建、目录改名均使旧预览失效 |
| W19 | 二进制文件、大小写路径、文件/目录互换 | 校验路径与类型；二进制显式选择版本并保留双方；不伪造文本合并 | PDF/图片冲突和跨平台路径碰撞不会静默损坏 |
| W20 | 多文件应用中断、租约丢失 | 持久步骤日志、操作前后快照；停止旧写者；进入明确恢复状态 | 每一步注入崩溃，恢复不重复 Git 命令、不覆盖第三方新内容 |
| W21 | 成员权限撤销、负责人离开 | 继承父项目权限，断开所有子工作区连接；暂停相关凭据任务并移交 | 已打开页面、历史/图片/API、后台任务均不能绕过撤销 |
| W22 | 共享链接意外扩大权限 | 旧匿名/token 链接只保留默认工作区语义；内部空间不可独立分享 | 猜测 workspaceId、直接访问内部 ID 不获得分支内容 |
| W23 | 评论、历史、编译结果串分支 | 明确存储空间和快照版本；作废迟到结果；评论来源可追踪 | 切换后旧 PDF、旧评论、旧 AI 回答不冒充当前结果 |
| W24 | 归档/删除分支时仍有人编辑 | 检查活动会话、脏内容、冲突与恢复任务；先保存恢复记录 | 删除/恢复演练可找回论文内容和对应元数据 |
| W25 | 多远端/凭据选错、远端不可达 | 显式绑定 remote/ref/凭据负责人；错误状态和最后成功时间；禁止自动换源 | 认证失败、限流、网络超时不被展示为“已同步” |
| W26 | Webhook 伪造、重复或乱序 | 验签、仓库绑定、投递去重；载荷只触发对账，不直接当正文 | 错签名/错仓库拒绝；重复/乱序事件不回退 refs |
| W27 | LFS、submodule、忽略文件遗漏 | 在导入/导出前检查支持范围；缺少真实资源时明确阻止或提示 | 不把 LFS 指针当 PDF 成功导入；忽略文件不被隐式删除 |
| W28 | 磁盘/资源耗尽损坏协作任务 | 写前容量检查、配额、失败保留记录；构建测试资源与数据卷分开 | ENOSPC 时停止应用并保留前后像，不报告成功 |
| W29 | Git 文本合并成功，但论文语义或编译失败 | 合并成功和编译/审阅状态分开；校验根文档与引用资源，运行指定快照编译；失败保留结果供人工处理，不自动回滚新编辑 | 不同文件修改造成缺失引用或 LaTeX 错误时，不能显示“论文验证通过” |
| W30 | 预览期间来源分支前进/改名/删除 | 合并任务固定来源 OID；应用前检查来源 ref，变化则标记过期并要求重新预览；保留旧草稿 | 来源分支新增提交后旧预览不能冒充合并了最新分支；来源删除也可找回草稿 |
| W31 | 任务完成时用户已切分支/关闭标签页 | 持久任务绑定项目、工作区、epoch、operationId；响应携带原身份；当前页面只接收匹配结果，其余进任务中心 | A 切到 Y 后，X 的 AI/编译/Git 结果不能写入 Y，也不能无故消失 |
| W32 | 订阅事件与读取快照交错，列表永远漏更新 | 使用可恢复事件游标或订阅后重读快照；客户端比较单调 revision；检测缺口后重新取快照 | 快照读取期间创建分支、解决任务或用户退出，各浏览器最终收敛且不回退 |
| W33 | 普通编辑者借 Full Access 或 /git 管理远端与自动任务 | 建立能力矩阵；内容编辑、共享 index、分支管理、远端/凭据/自动化管理分别授权；执行时重新校验 | 只读/普通编辑/管理员逐入口正反例；权限模式不能自行升级项目权限 |
| W34 | 清理/配额任务删除仍被冲突或恢复流程引用的草稿 | 记录引用关系和保留策略；活动事务、恢复引用、未完成草稿不可回收；过期前提示与导出；删除可审计 | 执行 GC 后未完成冲突和恢复仍可继续；完整备份包含 Git、文档及任务关系 |


| W35 | 两人同时创建同名分支，或分支删除后同名重建 | 以完整 ref 做唯一准入；初始化幂等；workspaceId 独立于名称；同名重建获得新身份，旧会话不可重新绑定 | 同时创建只得到一个 ready 工作区；中途失败可重试；旧会话不能写入重建分支 |
| W36 | 升级期间旧网页、旧服务或未启用 epoch 的工作区混用 | 按项目协商协议能力；未知/缺失版本不当作当前版本；兼容模式与强制校验模式明确分开；升级前检查所有写入链路 | 测试 undefined/null/数字版本及新旧客户端组合；不破坏旧工作区协作，也不放行受保护工作区的无版本写入 |
| W37 | 备份恢复使 epoch 回退，旧标签页误被当作有效会话 | 恢复后生成新的服务端恢复代次并撤销旧会话/任务租约；重新建立 Redis 状态；禁止只恢复 Mongo 或只恢复 Git 后直接接流量 | 恢复较早备份后重连旧网页、投递旧任务，均拒绝旧写入且保留恢复文本；核对 Git/正文/附件/任务对应关系 |
| W38 | 自动提交消耗人工暂存、提交不完整论文快照 | 自动任务发现人工暂存则暂停并提示；提交快照绑定已保存的文档版本，不提交浏览器未确认缓冲；不自动修改共享 index | A 暂存部分文件时自动任务不抢提交；B 在快照后继续写作使旧任务失效或仅提交明确冻结快照；新编辑仍保留 |


## 4. 共享冲突任务的用户体验

- 同分支写作者：醒目提示“存在未解决合并冲突”，显示文件数量、负责人、是否暂停自动应用/推送。
- 其他有权限的项目写作者：项目级摘要和跳转入口；不自动切换其编辑分支。
- 只读成员：在有权限的范围内查看状态，不获得写入或领取处理权限。
- 离线/重连用户：从服务端完整状态中恢复未完成任务，不能只靠一次弹窗。
- 当前处理者：在隔离合并草稿中逐文件解决，确认前看到最新版本验证结果。
- 其他成员：可查看处理进度；正文继续编辑会使旧草稿需要重新验证。不可宣称“处理人拿到租约后别人不能再编辑正文”。

冲突提醒不等于正文冻结；处理租约不等于替代版本检查。后台可继续 fetch，但受影响分支的自动应用和自动 push 暂停。

## 5. 建议配置与尚未验收的选择

以下为推荐起点，不是已经上线的保证：

- Webhook 可用时优先通知，周期对账补漏；本地无公网回调时先使用周期检查。
- 活跃项目远端检查可从 60 秒起步，空闲项目降低频率，失败指数退避并加入抖动；需以资源/限流测试调整。
- Presence 可从 20 秒心跳、60 秒过期起步；不得把过期前的网络间隔说成零延迟。
- 第一版自动获取远端提交与自动应用正文分开；自动应用默认关闭。
- 未提交网页编辑默认阻止自动应用；后续若支持重放到新基线，必须单独验证文本、结构和离线操作。
- 远端是否被团队用作正式发布基准属于项目策略；它不改变服务端编辑状态的真实性。
